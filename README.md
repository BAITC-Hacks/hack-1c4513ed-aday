# EKT StockPilot — автопилот закупа

Веб-сервис для закупщика ТОО «Электрокомплект». Он читает шесть выгрузок 1С для IEK и Systeme Electric, рассчитывает рекомендованный заказ по каждому коду 1С и показывает числовое обоснование. Отправки поставщику нет: менеджер корректирует количество, утверждает заказ и скачивает файл.

## Быстрый старт

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

На Linux/macOS используйте `source .venv/bin/activate`. Интерфейс доступен по адресу, который напечатает Streamlit. Ключи ИИ необязательны. При желании скопируйте `.env.example` в `.env` и заполните `OPENAI_API_KEY` либо `NVIDIA_API_KEY`. Приложение работает без них, используя детерминированный текст.

## Данные и допущения

- Исходные книги лежат в `data/raw/IEK/` и `data/raw/SystemeElectric/`: `sales_tx.xlsx`, `sales_monthly.xlsx`, `stock_monthly.xlsx`, `in_transit.xlsx`, `moq.xlsx`, `seasonality.xlsx`. Исходные файлы не меняются. `python scripts/inspect_data.py` печатает листы, размер и первые шесть строк каждого листа.
- Код 1С приводится к строке; конечный `_` сохраняется. Таблицы и строки заголовков находятся по ключевым словам. Итоговые и пустые строки отбрасываются. Из транзакций берутся только расходные накладные с 2025-01-01; возвраты с отрицательным количеством не считаются положительными продажами. Номера накладных в расчётном выводе и ИИ-запросах не передаются.
- Дата расчёта фиксирована: **22.09.2026**. Сентябрь 2026 исключён из истории полных месяцев, но его начальный остаток используется как текущий. Это приближение: движения с 1 по 22 сентября для IEK в текущий остаток не добавляются. Для Systeme Electric используется «Свободный остаток» из таблицы закупщика, если он заполнен.
- Для IEK в пути суммируются колонки документов; срок поставки — медиана дней от даты документа до даты ожидаемого поступления в заголовке. Для Systeme Electric берётся колонка «СЭ в пути», срок — **30 дней**. Даты ожидаемого поступления IEK могут быть плановыми, а не фактическими.
- MOQ IEK читается как кэшированное значение формулы через `openpyxl(data_only=True)`. Пустое, нечисловое или меньше 1 → 1. Для Systeme Electric берётся «Кратность». Отсутствующий в справочнике MOQ → 1.
- Сезонность бренда берётся из денежных продаж 2024–2025 и нормируется до среднего 1. Сезонность артикула используется при минимум 18 месяцах наблюдений, минимум 12 положительных месяцах и суммарных продажах от 60 единиц; иначе применяется бренд. Денежная сезонность бренда служит только приближением для количественного спроса.
- Накладные очищаются за **всю надёжную историю с января 2025**, включая оба периода сравнения роста. Кандидат на всплеск: количество больше `max(медиана + 5 × 1.4826 × MAD, 10 × медиана)` и 10 единиц; по артикулу нужно минимум четыре положительные строки. Если отгрузки сопоставимого размера (не меньше половины кандидата) встречались минимум в трёх разных месяцах какого-либо 12-месячного окна, содержащего этот месяц, спрос считается регулярным и сохраняется. Редкая строка исключается целиком. Дополнительного ограничения всего месяца медианой нет. Для 2024 без накладных используется односторонний месячный Hampel-фильтр. Исключённое количество и число всплесков сохраняются в объяснении.
- Месяц считается дефицитным, если начальный остаток ≤ 0 и следующий тоже ≤ 0 **или** продажи ниже половины типичного сезонного уровня. Типичный уровень — медиана очищенного и десезонализированного спроса за месяцы с положительным остатком. Спрос в дефицитном месяце восстанавливается до типичного уровня с сезонностью, если он выше факта.

## Формула заказа

Базовый спрос — взвешенное среднее очищенного, восстановленного и десезонализированного спроса за последние шесть полных месяцев (более свежие месяцы имеют больший вес). Рост — отношение этих шести месяцев к тем же шести месяцам год назад, ограниченное диапазоном **0.7–1.5**; при нехватке истории равен 1. Прогноз по месяцам умножает базу на рост и сезонный индекс.

ABC определяется по очищенному и восстановленному объёму за 12 полных месяцев: A до 80% накопленного объёма, B до 95%, далее C. Позиция, пересекающая границу, входит в предыдущую группу. Для Systeme Electric рядом показывается исходная «Категория 2026» закупщика; она не заменяет вычисленную ABC. Коэффициенты сервиса: A **1.65** (95%), B **1.28** (90%), C **1.04** (85%). Страховой запас: `z × σ × √((L+R)/30)`, где σ — стандартное отклонение месячного спроса за 12 месяцев. По умолчанию период пересмотра R = **30 дней**.

Потребность — помесячный прогноз, пропорционально дням в интервале от 22.09.2026 на `L+R` дней, плюс страховой запас. При продажах в менее чем четырёх из последних шести полных месяцев страховой запас ограничивается спросом за `L+R`. Если за эти шесть месяцев продаж не было **или** прогноз < 0.5 единицы/месяц, заказ принудительно равен нулю с объяснением «Нет устойчивого спроса». Иначе заказ — `max(0, потребность − остаток − в пути)` с округлением вверх до MOQ. Срочность по дням покрытия `(остаток + в пути) / (прогноз за месяц / 30)`: «Критично» при покрытии < L, «Высокая» при < L+14, иначе «Плановая». По умолчанию в таблице видны только позиции с рекомендацией заказа; переключатель «Показать все позиции» выводит и нулевые строки с предупреждением о размере таблицы.

## Интерфейс и ИИ

Фильтры поставщика, категории и срочности меняют только отображение. Период пересмотра и коэффициенты сервиса находятся в форме: изменение поля не запускает расчёт, нужна кнопка «Рассчитать». При первом открытии расчёт запускается автоматически. Тяжёлая часть (`load → clean → stockout → forecast`) кэшируется через `st.cache_data` по поставщику, папке источника и времени изменения шести файлов; лёгкая часть (`replenish`) при повторном нажатии пересчитывает только заказ. Время обеих частей печатается в консоль. Прогноз по артикулам рассчитывается векторизованными операциями pandas.

В таблице редактируется «Корректировка»; количества показываются целыми, прогноз — с одним знаком. Широкая колонка обоснования и карточка артикула дают полный текст. KPI «Поставщиков в заказе» считает поставщиков без смешения штук и метров. Карточка показывает факт, восстановленный спрос, дефицит, всплески, прогноз и шаги расчёта. Для Systeme Electric есть сравнение с ручным заказом.

Экспорт до утверждения недоступен. После «Утвердить заказ» основная кнопка скачивает **один Excel**: листы IEK и Systeme Electric содержат код 1С, артикул, наименование, количество, срочность и обоснование; лист «Сводка» содержит поставщика, число позиций и дату расчёта. Шапки выделены, ширина колонок настроена. Файл сохраняется в `output/stockpilot_order.xlsx`. Дополнительно доступны CSV по поставщикам с четырьмя колонками для 1С. Отправки поставщику нет.

В боковой панели можно загрузить новые выгрузки для выбранного поставщика: шесть полей с русскими подписями принимают `.xlsx`. Кнопка «Проверить и использовать» сохраняет файлы в `data/uploads/`, проверяет их существующим загрузчиком и переключает расчёт на них; ошибка называет неподходящий файл. Другой поставщик продолжает работать со своим текущим источником. «Вернуться к демо-данным» возвращает оба источника к `data/raw/`. По умолчанию используются демо-выгрузки. `data/uploads/` исключён из git.

ИИ вызывается только кнопкой для выбранной позиции или топ-20, а также для чата. По умолчанию OpenAI использует `gpt-4.1-nano`, резервный NVIDIA — `meta/llama-3.1-8b-instruct` через совместимый API. Тайм-аут 12 секунд на запрос, при ошибке используется шаблон. ИИ получает агрегаты без номеров накладных и данных клиентов. [Официальная документация OpenAI подтверждает поддержку Chat Completions для `gpt-4.1-nano`](https://developers.openai.com/api/docs/models/gpt-4.1-nano).

## Проверка

```powershell
python -m pytest -v
python scripts/run_full.py
python scripts/audit.py
python scripts/diagnose_growth.py
python -m streamlit run app.py --server.headless true
```

Тесты проверяют влияние источников, сезонность, компенсацию дефицита, симметрию очистки роста, отсутствие заказа без спроса, сохранение регулярного опта, объяснения, структуру Excel и импорт. Smoke-тест загрузки IEK пропускается при отсутствии данных. `scripts/run_full.py` печатает заказ, топ-10 критичных и проверку кода `010500008_`; `scripts/audit.py` печатает доли роста на 0.70, исключённого объёма и месяцы покрытия; `scripts/diagnose_growth.py` сравнивает сырые и очищенные отношения год к году.

## Структура

`src/loader.py` — чтение и нормализация; `outliers.py` — всплески; `stockout.py` — дефицит; `forecast.py` — прогноз; `replenish.py` — ABC и заказ; `explain.py` — формульный текст; `llm.py` — ИИ с резервом; `pipeline.py` — тяжёлая и лёгкая части; `export.py` — Excel; `uploads.py` — проверка и сохранение импорта; `config.py` — параметры. `app.py` — Streamlit. `scripts/` — разведка и аудит. `data/cache/` содержит pickle кэш и исключён из git.

## Ограничения

Цен и идентификаторов клиентов в выгрузках нет; ABC поэтому построена по количеству, а не выручке. Прогноз не оценивает промо, замены товаров и незарегистрированные поставки. У Systeme Electric срок поставки фиксирован. На демо-данных заметная часть артикулов остаётся на нижней границе роста 0.70: у многих сырые продажи марта–августа 2026 ниже тех же месяцев 2025 ещё до очистки; код не повышает рост искусственно. В отдельные месяцы доля редких исключённых строк может быть выше среднего. Рекомендации требуют проверки закупщиком перед утверждением. Изменения исходных книг обновляют кэш по времени модификации файла; после изменения логики загрузчика удалите `data/cache/` вручную.
